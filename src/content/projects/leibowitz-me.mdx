## The problem

The last version of this site was written in 2014, in hand-rolled jQuery and CSS, before React was the default way to build anything. Twelve years on, the design was dated and so was everything it said about me. I also wanted somewhere of my own to publish writing and keep lists, rather than renting space on someone else's platform.

## What it does

This is my online resume and everything around it: where I have worked, what I have built on my own time, what I have written, and a few lists of things I like enough to rank.

## How it's built

Astro and MDX, styled with Tailwind, deployed to Cloudflare. It ships no framework runtime and no JavaScript files at all, just under two kilobytes of hand-written script on the homepage, so a page arrives as HTML and renders straight away.

Images are optimized as part of the build, every post gets its own link-preview card drawn for it, and each pull request publishes a working preview of itself.

## What I'd do differently

Every word on this site lives in a markdown file committed to the repo. That was the right call for getting it built and it is the wrong one for living with it. Changing anything means pulling the repo, starting a dev server, writing markdown, previewing it locally, then committing and pushing before it is real. That is a lot of ceremony for fixing a typo, and enough friction that small changes wait for a batch.

What it needs is an admin only I can reach: write and edit in the browser, press publish, and have publishing trigger the rebuild on its own. The site stays a static build, because that is what makes it fast to serve and cheap to host. What changes is that editing a sentence stops requiring a terminal.
